# 13. Glossary

Short definitions in alphabetical order. The number in brackets is the page that explains each term in full.

- **Action space**: the set of things an agent can do in one step. CoALA splits it into external actions on the world and internal actions such as retrieving, reasoning and learning. (1)
- **Agent**: a system in which a language model directs its own steps and tool use, usually by calling tools in a loop until a task is done. Equivalently, a model plus a harness. (1)
- **Agent-computer interface (ACI)**: the tools and formats through which an agent works with a computer, designed for a model rather than a person. (5)
- **Agentic system**: Anthropic's umbrella term covering both workflows and agents. (1)
- **Assistant message**: a message that contains the model's own earlier output, including its tool calls. (3)
- **Attention budget**: the idea that each token in the context uses up part of the model's limited capacity to attend, so irrelevant tokens have a cost. (3)
- **BM25**: a long-established keyword-matching method for ranking documents, used in RAG to catch exact terms that embeddings miss. (8)
- **Chain of thought**: having the model write out its reasoning step by step before it answers. (4)
- **Chunk**: a short passage of a document, the unit that RAG stores and retrieves. (8)
- **Code execution (code mode)**: letting the model write a program that calls tools inside a sandbox, so that only the program's printed output returns to the context. (5)
- **Compaction**: summarizing a long conversation and continuing with the summary in place of the full history. (7)
- **Consolidation (reflection)**: periodically turning raw memory records into shorter summaries or lessons. Useful, but it can distort memory. (8)
- **Context**: everything the model sees in one call. (3)
- **Context engineering**: deciding what goes into the context on every call of an agent's loop. (7)
- **Context rot**: the decline in a model's performance as its context grows longer, even on tasks of fixed difficulty. (3)
- **Context window**: the maximum number of tokens the model can handle in one call, input and output together. (3)
- **Embedding**: a list of numbers that represents a piece of text, made so that texts with similar meanings get similar numbers. (8)
- **Episodic memory**: records of specific past events, such as earlier transcripts. (8)
- **Error analysis**: reading real transcripts, noting failures and grouping them into categories before designing tests. (10)
- **Eval**: a test that measures how well an AI system performs. (10)
- **Few-shot and zero-shot prompting**: giving the model a few worked examples of a task, or none. (4)
- **Function calling**: the model writing a structured call to a tool, with arguments that match the tool's declared parameters. (5)
- **Grader**: whatever decides whether a trial succeeded. Graders can be code-based, model-based or human. (10)
- **Guides and sensors**: in Böckeler's terms, the parts of a harness that steer the agent before it acts (guides) and the parts that check its work afterwards (sensors). (6)
- **Harness**: all the software around the model that turns it into an agent. In narrower usage, only the loop that calls the model and routes its tool calls. (6)
- **Inner and outer harness**: the part of the harness that the agent's makers ship, and the part you add for your own project. (6)
- **In-context learning**: a model picking up a task from instructions or examples in its input, with no change to its weights. (4)
- **Just-in-time retrieval**: keeping short references in the context and loading the full content only when it is needed. (7)
- **Knowledge cutoff**: the date after which the model's training data contains nothing. (2)
- **LLM (large language model)**: a neural network trained on large amounts of text to predict the next token. (2)
- **LLM-as-judge**: using a language model as a grader. (10)
- **MCP (Model Context Protocol)**: an open standard that lets any compatible application use the tools and data offered by any compatible server. (5)
- **Memory**: information an agent stores outside the model and its current context and reads back later. In the narrow sense, knowledge from experience that is kept across sessions. (8)
- **Multi-agent system**: several agents, each with its own loop and context, working on one task. (9)
- **Orchestrator-worker pattern**: a lead agent that plans, hands pieces of work to subagents and combines their results. (9)
- **pass@k**: the chance that at least one of k trials succeeds. (10)
- **pass^k**: the chance that all k trials succeed. (10)
- **Procedural memory**: knowledge of how to do things, held in the model's weights, in code, in instructions and in skills. (8)
- **Progressive disclosure**: showing the model a short summary first and loading the details only when they are needed. (5)
- **Prompt engineering**: writing prompts that reliably produce the behaviour you want. (4)
- **RAG (retrieval-augmented generation)**: retrieving relevant passages from a document collection and putting them in the context before the model answers. (8)
- **Reranking**: a second model rescoring retrieved candidates and keeping the most relevant. (8)
- **Reward hacking**: raising a score without doing the intended work, such as editing tests instead of fixing code. (11)
- **RSI (recursive self-improvement)**: in the labs' sense, AI fully autonomously designing and developing its own successor. (11)
- **Sandbox**: an isolated environment where an agent's code runs without being able to damage anything else. (6)
- **Semantic memory**: stored facts, such as a user's preferences or a project's structure. (8)
- **Session**: one continuous run of an agent. In Anthropic's Managed Agents, the permanent log of everything that happened in that run. (6)
- **Skill**: a folder with a SKILL.md file of instructions, plus any scripts or references, that the model loads only when a task needs it. (5)
- **Stateless**: keeping nothing between calls, which is true of the model itself. (2)
- **Subagent**: an agent started by another agent to do one piece of work in its own context. (9)
- **System prompt**: standing instructions sent at the start of every call that set how the model should behave throughout. (4)
- **Task, trial, transcript and outcome**: in evals, one test case; one attempt at it; the full record of that attempt; and the final state of the environment afterwards. (10)
- **Token**: the unit of text a model reads and writes, roughly three to four characters of English. (2)
- **Tool**: a function outside the model that the model can ask the harness to run. (5)
- **Tool call and tool result**: the model's structured request to run a tool, and the output the harness sends back. (5)
- **Tool definition**: a tool's name, plain-language description and parameter schema, sent to the model with every call. (5)
- **Vector store**: a database that finds the stored embeddings closest to a given one. (8)
- **Weights**: the learned numbers inside the model, fixed once training ends. (2)
- **Workflow**: a system in which code, not the model, decides the sequence of steps. (1)
- **Working memory**: the information active in the current step, held in the context. (8)
