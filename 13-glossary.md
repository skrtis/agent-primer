# 13. Glossary

Alphabetical reference. Numbers in parentheses point to the page that explains each term in full.

- **Agent:** a system where a language model chooses its own steps and tool calls in a loop (`model + harness`). (1)
- **Agent-computer interface (ACI):** tools and output formats designed specifically for a language model rather than a human user. (5)
- **Agent loop:** the repeated cycle where the harness sends context to the model, runs any requested tools, appends the results, and repeats until done. (1, 6)
- **Agentic system:** Anthropic's umbrella term covering both fixed workflows and autonomous agents. (1)
- **Assistant message:** a message holding the model's earlier output, including any tool requests. (3)
- **Attention budget:** the model's limited capacity to pay attention across its input, making irrelevant tokens costly. (3)
- **Benchmark:** a fixed set of tasks and scoring rules used to compare systems. (10)
- **BM25:** a classic keyword-matching search method, paired with embeddings in RAG to catch exact IDs and terms. (8)
- **Brief:** the instructions a lead agent gives a subagent, which are everything the subagent knows about its task. (9)
- **Capability eval:** tasks the agent currently struggles on, used to measure improvement. (10)
- **Chain of thought (CoT):** asking a model to write out reasoning steps before giving its final answer. (4)
- **Chunk:** a short passage of a document stored and searched as one unit in RAG. (8)
- **Code execution (code mode):** letting the model write a short script inside a sandbox that calls tools and prints only the filtered result back into context. (5)
- **Compaction:** summarizing older parts of a conversation in place so it stays inside the context window. (6, 7)
- **Computational vs. inferential checks:** exact code checks (tests, linters: fast, cheap) vs. checks done by another model (can judge meaning, but slower and less consistent). (6)
- **Consolidation (reflection / dreaming):** periodically turning raw logs or notes into shorter summaries or lessons; can distort details if rewritten repeatedly without checks. (8)
- **Context:** all the text (tokens) sent to the model in a single call. (3)
- **Context clash:** contradictory instructions or facts appearing in the same context. (7)
- **Context confusion:** irrelevant material (like unused tool definitions) pulling the model toward worse choices. (7)
- **Context distraction:** a very long history causing the model to lean too heavily on past turns instead of reasoning freshly. (7)
- **Context engineering:** deciding what goes into the model's context on every turn of the agent loop. (7)
- **Context isolation:** keeping a subagent's messy exploration inside its own separate context so only a short summary returns to the lead agent. (9)
- **Context poisoning:** an error or hallucination entering the context and snowballing across later turns. (7)
- **Context rot:** a drop in model accuracy as input length grows, even when task difficulty stays fixed. (3)
- **Context window:** the maximum number of tokens (input plus output) a model can handle in one call. (3)
- **Embedding:** a vector representation of text used to search for passages with similar meaning. (8)
- **Environment:** whatever an agent's tools act on (a codebase, browser, database, or lab instrument). (1)
- **Error analysis:** reading real transcripts and grouping actual failures into categories before building graders. (10)
- **Eval:** a test suite that measures how well an agent performs. (10)
- **Evaluation harness:** the testing software that runs eval tasks and grades them (separate from the agent harness). (10)
- **Extended thinking:** reasoning text a model writes before its final answer to work through hard problems. (2)
- **Few-shot / zero-shot prompting:** giving the model a handful of worked examples in the prompt, or none. (4)
- **Function calling:** the model writing a structured request to run a tool with inputs matching its declared format. (5)
- **Grader:** code, a language model, or a human deciding whether a trial succeeded. (10)
- **Guides and sensors:** outer-harness pieces that steer the agent before it acts (guides) vs. check its work afterward (sensors). (6)
- **Harness:** the software wrapped around the model to run the loop, tools, context, and safety checks (in narrow usage, just the loop itself). (6)
- **Harness engineering:** building and maintaining the software around the model. (4, 6)
- **In-context learning (ICL):** a model picking up a new task solely from instructions or examples in its input, with its weights unchanged. (4)
- **Inference call (call):** one exchange where input text is sent to the model and output text comes back. (2)
- **Initializer agent:** a one-time agent that sets up progress files, feature checklists, and initial commits at the start of a long project. (6)
- **Inner vs. outer harness:** what the agent's makers ship (loop, system prompt, built-in tools) vs. what you add for your own project (`CLAUDE.md`, skills, hooks, checks). (6)
- **Iteration:** revising an output in a loop until it passes a test. (11)
- **JSON Schema:** a standard format for listing what inputs a tool expects and their types. (5)
- **Just-in-time retrieval:** keeping short pointers (like file paths) in context and loading full contents only when needed. (7)
- **Knowledge cutoff:** the date when the model's training data stopped. (2)
- **LLM (large language model):** a neural network trained on huge text datasets to predict the next token. (2)
- **LLM-as-judge:** using a language model with a rubric as a grader. (10)
- **Long-term memory:** information saved outside the context that survives across sessions (files, logs, databases). (8)
- **Lost in the middle:** models using information near the start and end of long inputs more reliably than information in the middle. (3)
- **MCP (Model Context Protocol):** an open standard letting any compatible agent app connect to tool and data servers without custom connectors. (5)
- **MCP host, client, and server:** the agent app (host), its connection to one server (client), and the program exposing the tools and data (server). (5)
- **Memory:** information saved outside the model and read back into context later (narrowly: cross-session knowledge gained from experience). (8)
- **Message and role:** turns in the context labeled as coming from `system`, `user`, `assistant`, or a tool result. (3)
- **Multi-agent system:** several agents with separate loops and contexts working together on one task. (9)
- **Offloading:** saving large tool outputs to files and keeping only a path and short snippet in context. (7)
- **Orchestrator-worker pattern:** a lead agent dividing work among subagents and combining their summaries. (9)
- **Outcome:** the final state of the environment when a trial ends. (10)
- **Parallelism:** running independent subtasks at the same time across subagents. (9)
- **pass@k:** chance that at least one of `k` trials succeeds. (10)
- **pass^k:** chance that all `k` trials succeed. (10)
- **Permissions:** harness rules controlling which actions run automatically, ask the user first, or are blocked. (6)
- **Post-training:** instruction tuning, RLHF, RLVR, and tool-use RL done after pretraining. (2)
- **Pretraining:** initial next-token prediction training over massive text corpora. (2)
- **Progressive disclosure:** loading short summaries upfront and reading full details only when needed. (5)
- **Prompt / prompt engineering:** input text steering a model, and the practice of writing it reliably. (4)
- **RAG (retrieval-augmented generation):** searching a document collection for relevant passages and adding them to context before answering. (8)
- **Regression eval:** tasks passing near 100%, used to catch changes that break working behavior. (10)
- **Reranking:** a second model rescoring retrieved RAG candidates to keep only the best few. (8)
- **Reset:** starting a fresh agent with an empty context from a structured handoff note, instead of summarizing in place. (6)
- **Reward hacking:** raising a test score without doing the intended work (such as editing tests instead of fixing code). (11)
- **Right altitude:** prompt specificity that guides behavior clearly without brittle step-by-step micromanagement. (4)
- **RLHF / RLVR:** reinforcement learning from human preferences vs. automatically verifiable rewards (passing tests, exact math). (2)
- **RSI (recursive self-improvement):** improvement that also improves a system's ability to make further improvements; in lab safety frameworks, AI autonomously building its own successor. (11)
- **Sandbox:** an isolated environment where agent code can run without harming the host computer or reading secrets. (6)
- **Scaffolding:** harness pieces built to make up for weaknesses of the current model. (12)
- **Self-improvement:** a lasting change to the system (new skill, updated memory, edited harness) that improves results on a fixed test. (11)
- **Session:** one continuous run of an agent; in Managed Agents, the permanent log of everything that happened in that run. (6)
- **Short-term memory:** the current context window, discarded when a session ends. (8)
- **Skill:** a folder with a `SKILL.md` instruction file (plus optional scripts or references) loaded on demand via progressive disclosure. (5)
- **Stateless:** keeping nothing in memory between calls, which is true of the model itself. (2)
- **Structured note-taking:** saving plans and progress to external files (`NOTES.md`, to-do lists) so they survive compaction and restarts. (7)
- **Subagent:** a secondary agent started by a lead agent with its own separate context. (9)
- **System prompt:** standing instructions sent in the `system` role on every call. (4)
- **Task, trial, transcript, and outcome:** an eval test case; one attempt; the full record of that attempt; and the final state afterward. (10)
- **Token:** a short unit of text (~3 to 4 English characters) that a language model reads and writes. (2)
- **Tool:** an external action the harness runs when the model asks for it. (5)
- **Tool call / tool result:** the model's structured request to run a tool, and the output the harness sends back. (5)
- **Tool definition:** a tool's name, description, and input format sent to the model on every call. (5)
- **Vector store:** a database built to find stored embeddings closest in meaning to a query. (8)
- **Verification:** checking whether an agent's work is actually right, kept separate from the work itself. (12)
- **Weights:** the learned parameters inside a model, fixed once training ends. (2)
- **Workflow:** a system where code, not the model, decides the sequence of steps. (1)
